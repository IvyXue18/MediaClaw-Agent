# 架构与权限边界

## 目标架构

```text
Codex adapter ─────┐
Claude adapter ────┼─> MediaClaw Broker (127.0.0.1) <─安全连接─> 浏览器插件
WorkBuddy adapter ─┘              │                         │
                                  │                         ├─ 页面读取与采集
                                  ├─ 设备身份与会话路由      ├─ 会员/积分校验
                                  ├─ 任务队列与幂等          └─ 人工确认
                                  └─ 状态与恢复
```

Skill 是 Agent 的方法说明，不执行浏览器采集；MCP adapter 把宿主的标准工具调用转换成 MediaClaw 协议；Broker 是每台电脑共享的一份本机运行时；浏览器插件是最终授权与执行边界。

## 仓库边界

本公开仓库负责：

- Codex、Claude Code、WorkBuddy 的薄安装清单。
- 共享 Skill、MCP 工具定义、版本化分析方法与返回契约。
- 本机设备身份、Broker、宿主 adapter 和跨宿主任务路由。
- 不依赖真实平台登录态的协议测试。

浏览器插件主仓库负责：

- 小红书、抖音页面适配和字段解析。
- 数据池与 MC 工作台数据的实际读取。
- 基础采集、增强采集、评论、OCR、逐字稿等具体执行器。
- 激活码、会员、积分、报价确认和插件 UI。

两边通过版本化协议协作。公开仓库不得复制平台解析器、Cookie、内部接口密钥或任何绕过插件权限的实现。

## 权限原则

权限永远由浏览器插件按现有产品规则裁决，Agent 只能请求能力：

- 已有本地数据池和用户在 MC 中已拥有的数据：允许读取；本地读取不计成本。
- 需要数据库或额外服务资源的读取：由插件判断会员资格。
- 无激活码：允许单条笔记获取、基础字段批量采集及基于已获数据的 Agent 分析。
- 有激活码：开放与现有插件一致的完整采集能力。
- AI 分析和内容生成可以由宿主 Agent 使用 Skill 完成，不重复收取 MediaClaw AI 成本。
- 增强采集、OCR、评论或逐字稿等不能因 Agent 会分析而绕过插件原有资格、积分或确认。
- V0.3 不开放 BYOK；逐字稿必须先由插件报价，再凭 `quoteId` 确认。

## 设备与并发

每个宿主 adapter 生成独立密钥对，私钥只保存在本机，并以设备指纹供用户核对。目标架构由单一 Broker 持有浏览器端口，各宿主通过本机 IPC 连接 Broker，避免多个 MCP 进程争抢同一端口。

浏览器操作采用全局串行队列；纯本地读取可受控并发。Broker 必须支持任务幂等、取消、超时、结果路由和进程重启后的有限恢复。

## 当前实现与剩余边界

V0.3 Alpha 已完成“共享 Broker + 每宿主薄 adapter”拆分。Broker 独占 `127.0.0.1:17373`，每个宿主以独立设备密钥注册；浏览器插件按设备分别挑战、配对、建立会话和撤销。浏览器采集仍使用全局串行队列，同一台电脑上的多个宿主可以同时提交任务，但不会并行操纵同一个页面，也不能读取其他宿主的任务结果。

当前仍属于预览版：Codex 与 Claude Code 的清单和协议已验证，WorkBuddy 只有候选清单；浏览器端会员、积分、OCR 与逐字稿仍需完成真实激活码验收。运行时发布包提供校验值与 GitHub 构建来源证明，但浏览器界面暂不把它显示为“官方已验证来源”。
