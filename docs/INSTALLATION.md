# 安装与连接 MediaClaw Agent

MediaClaw Agent 需要与 MediaClaw 浏览器插件配合使用。普通用户不需要自行配置端口、令牌或运行服务。

## 第一步：准备浏览器插件

1. 安装或升级 MediaClaw 浏览器插件。
2. 在 MediaClaw 插件中完成有效会员验证。
3. 在浏览器中登录需要使用的小红书或抖音账号。
4. 确认插件可以正常打开。

## 第二步：把安装交给 Agent

在 Codex 或 WorkBuddy 的新对话中直接发送：

> 请从 https://github.com/IvyXue18/MediaClaw-Agent 通过当前宿主的 marketplace 安装、升级或修复 MediaClaw 官方接入包，完成后继续检查连接并引导我批准设备。平台和芯片识别、官方运行时准备、SHA-256 校验及连接复查都由你完成；不要让我下载 ZIP、选择 `.exe` 或使用终端。

Agent 负责识别宿主、注册官方 marketplace 和安装接入包。接入包第一次启动时会自动识别 Windows、macOS 或 Linux 及当前芯片，从官方 Release 获取唯一匹配的原生运行时并校验；用户不需要安装 Node、Bash、WSL 或 Git Bash。首次安装发生在当前对话已经启动之后时，宿主可能要求重新打开应用或进入一个已加载插件的新对话；Agent 应说明原因并把下一步收敛为一个明确的界面动作，不要求用户输入安装命令。

当前原生运行时覆盖 macOS x64/ARM64、Windows x64/ARM64，以及 Linux glibc/musl 的 x64/ARM64。浏览器或系统策略完全禁止本机程序、GitHub 下载或 `127.0.0.1` 回环连接时，Agent 必须报告具体受限环节，不能把它误报为安装成功。

## 豆包工作本地开发接入

豆包工作目前没有本地自定义 MCP 配置导入入口。本地开发接入需要用户在“技能 · 连接器 · 伙伴”中保存一次 STDIO 连接器，但安装 Agent 必须先解析本机路径、完成握手预检，并按界面顺序给出完整填写表；不能让用户参照仓库 JSON 自己猜。

本地连接器固定字段如下，其中尖括号内容必须在展示给用户前替换为本机真实绝对路径：

| 配置项 | 填写值 |
| --- | --- |
| 服务器名称 | `mediaclaw` |
| 类型 | 本地电脑 / 自定义连接器 |
| 传输类型 | `STDIO` |
| Command | `<MediaClaw-Agent绝对路径>/plugins/mediaclaw/scripts/launch-agent-local.cmd` |
| CWD | `<MediaClaw-Agent绝对路径>/plugins/mediaclaw` |
| 参数 / Args | 留空 |
| `MEDIACLAW_AGENT_HOST` | `doubao-work` |
| `MEDIACLAW_AGENT_DEVICE_NAME` | `MediaClaw Agent (豆包工作)` |
| `MEDIACLAW_AGENT_CHANNEL` | `local` |
| `MEDIACLAW_AGENT_NODE` | 当前 Node.js 22 或更高版本可执行文件的绝对路径；Windows 必须指向 `node.exe` |

填写时变量名和值必须分栏输入，不加引号、不写等号、不留首尾空格。设备名必须完整保留空格、括号和“豆包工作”。Command 与 CWD 都必须是绝对路径，Args 必须真正留空。

在让用户保存前，安装 Agent 必须使用同一组 Command、CWD 和四个环境变量，在 GUI 常见的精简 `PATH` 下完成 MCP `initialize` 和 `tools/list`；只有服务名为 `mediaclaw-agent-adapter` 且工具列表包含 `mediaclaw_connection_status` 才算预检通过。宿主保存后仍应以连接器管理页真实列出工具为最终成功标准。

连接失败时保留并编辑现有的 `mediaclaw`，不要创建第二个。优先按以下顺序定位：

1. Node 路径不存在或版本低于 22：重新解析 `MEDIACLAW_AGENT_NODE` 的绝对路径。
2. Command 或 CWD 不存在：重新定位长期保存的 Agent 仓库，禁止使用下载临时目录。
3. 权限不足：确认启动脚本可执行以及仓库目录可读取。
4. `TRANSPORT_CLOSED`：只在豆包连接器管理页关闭后重新启用一次，不结束相关进程、不重复卸载。

## 后续更新

在已有 MediaClaw 的 Codex 或 WorkBuddy 对话中直接说“升级 MediaClaw Agent”即可。这句话本身代表明确授权；Agent 会自行刷新官方 marketplace、安装、核验版本并保存原任务，不向用户展示或要求用户执行终端、CLI、斜杠命令、缓存清理或路径操作。

安装完成后必须完全退出并重新打开当前宿主。运行中的旧对话不能热加载新 Skill/MCP，同一进程里再建对话也不能作为新版生效证据。重开后只有状态显示新版已经真实激活，才会自动继续原任务；已有设备批准默认复用。正式版更新只跟随正式 Release，不跟随 prerelease。

从旧版升级时，marketplace 仍然是唯一版本来源。升级后的第一次启动会在宿主提供的持久插件数据目录中准备当前平台的新运行时，原设备身份与浏览器批准不会因运行时替换而清空。原先“显示已安装但始终未连接”的用户可以再次发送同一条安装提示词；Agent 应刷新 marketplace、修复缺失运行时并复查连接，不要求先卸载。

如果自动升级失败，让 Agent 直接说明失败发生在“检查、安装、验版、重开激活”中的哪一步即可，不需要用户改用命令行修复。

## 第三步：批准连接

1. 在新会话中说：“检查 MediaClaw 连接状态。”
2. 打开 MediaClaw 浏览器插件 → 设置 → Agent 接管。
3. 开启“允许本机 Agent 调用”。
4. 核对当前 Agent 名称，在待确认列表中点击“批准”。
5. 回到 Agent，再次说：“检查 MediaClaw 连接状态，并告诉我现在能做什么。”

每个 Agent 需要分别批准。撤销其中一个不会影响其他已经批准的 Agent。

## 连接批准与采集确认

批准设备允许 Agent 连接社媒虾，不代表批准后续所有采集。当前源码 `0.3.2` 的统一确认改进尚未正式发布，不会在运行中的 `0.3.1` 会话里自动生效；应以已安装版本的工具与 Release 说明为准。

新版会先读取已有数据，简要说明必要的采集范围，并核对当前任务已有的同意。“可以”“好”“开始吧”都能确认方案，多组搜索可一次同意后连续执行，不要求固定口令、逐组回复或重新批准相同范围。你明确要求执行同样具体范围时也可直接继续；尚未授权的范围才会询问，沉默或拒绝不会被当成批准。扩大时间、增加评论或详情等超出授权的变化仍需同意。新增逐字稿另按报价确认，清理先看实际删除范围，私信仍在插件中最终确认发送。

## 常见问题

### 安装后没有检测到 Agent

- 确认安装完成后创建了全新的 Agent 会话。
- 确认 MediaClaw 浏览器插件已经开启。
- 回到 Agent 再次要求它检查连接状态。
- 如果仍未连接，让 Agent 报告具体安装状态和错误信息，不要反复重装。

### 一直显示等待批准

打开浏览器插件的“Agent 接管”，检查待确认列表并批准当前 Agent。不要把激活码、Cookie、Token 或任何本机令牌发给 Agent。

### 采集过程中要求处理浏览器

登录失效、验证码、平台限制或页面异常时，MediaClaw 可能暂停任务。按浏览器中的提示处理后，再让 Agent 查询原任务状态。

### 为什么有些能力不能使用

当前源码新增了已连接插件能力核查，正式发布前已安装会话不会自动获得。新版会区分当前 Agent 可调用、由 Agent 编排分析、需要插件最终确认和插件独有的操作；相同版本号或连接成功不代表每个功能都已接入。私信发送仍需在插件“最近任务”中核对，清理则先展示本次实际删除与保留范围，等待明确确认。

Agent 接管需要有效会员；逐字稿等计费能力还需要足够积分和执行前确认。平台登录状态、页面状态和安全限制也可能影响任务。让 Agent 说明缺少的条件和最小下一步，不要让它尝试绕过插件提示。

## 卸载

先在 MediaClaw 浏览器插件的“Agent 接管”中撤销对应 Agent，再使用 Codex 或 WorkBuddy 自己的插件管理入口卸载 MediaClaw。
