# 内容任务书方法

- Method ID: `evidence-content-brief-v1`
- Version: `1.0.0`
- Kind: generation

## 目标

在写正文前，把研究证据转成一份可以直接执行的内容任务书，避免 Agent 从“方向不错”跳到泛化成稿。

## 必需输入

- 一个已选择的选题。
- 目标平台、读者和期望行动。
- 可使用的真实事实、案例、过程和数据。
- 不得声称的内容。
- 可选的已保存风格档案。

## BUILD 任务书

### B — Brief

- 目标读者与触发场景
- 核心矛盾
- 唯一主张
- 读完后的认知或行动变化
- 内容形式和长度

### U — Unique angle

明确这篇内容与现有样本的差异来自对象、场景、判断、证明、过程还是结构。只能写真实差异。

### I — Information proof

建立“主张—证据”表：

```text
主张：
证据：
证据来源：
缺失时如何处理：删除 / 降级为经验判断 / 请用户补充
```

### L — Language and format

确定：

- 标题承诺强度
- 开头进入方式
- 段落节奏
- 是否需要步骤、案例、对比、图示或口播提示
- CTA 类型

### D — Diagnose

预先检查最可能出现的风险：证据不足、选题过宽、标题过度承诺、风格盖过事实或 CTA 与内容目标不一致。

## 输出契约

1. 一句话创作任务。
2. 目标读者、场景、矛盾、主张和行动。
3. 新角度及其证据依据。
4. 可用事实与禁止编造清单。
5. 2～3 个标题方向。
6. 分段大纲；每段包含：
   - 本段任务
   - 关键内容
   - 使用证据
   - 读者状态变化
7. 视觉或视频制作提示。
8. 成稿前待用户补充的信息。

用户只要求大纲时到此为止；用户要求完整内容时，再读取 [证据驱动成稿方法](content-drafting.md)。
