# 单篇内容深度拆解方法

- Method ID: `single-note-breakdown-v1`
- Version: `2.0.0`
- Tool: `mediaclaw_capture_note`

## 目标

还原一篇内容如何建立承诺、组织信息和获得反馈，并将可迁移机制与不可复制素材分开。不要只做段落摘要。

## 默认证据

- 单条内容详情：返回插件本次实际采集并保存的完整字段。
- 单条评论：保持插件现有单条路径，不增加 Agent 专属条数限制。
- 图片 OCR：有效套餐能力。
- 视频逐字稿：先 `mediaclaw_quote_video_transcript`，用户明确同意后再用 `quoteId` 确认。

缺少 OCR 或逐字稿时，继续分析已知的标题、正文和互动数据，但不得推断未读取的画面或口播。不得提供 BYOK、本地模型或其他供应商绕过参数。

## 分析步骤

1. 复原内容任务：
   - 写给谁
   - 发生在什么场景
   - 解决什么矛盾
   - 承诺什么变化
   - 希望用户采取什么行动
2. 标记内容结构：
   - 标题与封面入口
   - 开头承诺
   - 信息展开
   - 证明与示范
   - 转折和异议处理
   - 行动引导
   - 结尾闭环
3. 合并正文、OCR 或逐字稿，判断标题承诺是否真正兑现。
4. 从评论中区分：
   - 被验证的吸引点
   - 未解决的问题
   - 反对或不信任
   - 行动和购买意图
   - 表达误读
5. 把结果分为：
   - 可迁移机制：结构、证明、信息顺序和形式。
   - 条件性机制：只有具备特定受众或资源时成立。
   - 不可复制素材：个人经历、成绩、案例和独特身份。
6. 给出一个最值得迁移的机制和一个最大风险，不堆砌技巧。

## 输出契约

1. 一句话内容机制判断。
2. 数据覆盖和媒体理解缺口。
3. 人群、场景、矛盾、承诺、证明和行动。
4. 标题—开头—展开—证明—结尾结构图。
5. 评论验证与反例。
6. 可迁移、条件性和不可复制部分。
7. 用户需要创作时：
   - 选题：读取 [证据驱动选题方法](topic-ideation.md)。
   - 大纲：读取 [内容任务书方法](content-brief.md)。
   - 成稿：读取 [证据驱动成稿方法](content-drafting.md)。

## 禁止

- 表现数据不能证明具体因果。
- 不把评论样本当作全部受众。
- 不根据未提取的图片或口播虚构内容。
- 不直接复用原作者的个人经历、数据、案例或独特句子。
